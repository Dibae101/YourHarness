YourHarness

Pool the devices you already own into one workspace for AI work. Open a Linux terminal from any of them, and the jobs you run there borrow processors, memory and storage from the rest.

Prototype running on a Mac, a Windows PC, an iPad and an iPhone Next: a Python rewrite with a native agent

Why

AI work keeps outgrowing the machine in front of you. A language model with 8 billion parameters, compressed to 4 bits, needs about 5 GB of memory. That is more than a 4 GB laptop has, before the browser and the operating system take their share.

Most people who do this work already own several devices that sit idle for most of the day. YourHarness connects them into one pool, so a small laptop can run work that none of the devices could run alone.

What already works

The prototype is a small server and a web page. Each device opens the page and joins the pool. A job is cut into pieces, and every device takes a new piece whenever one of its threads is free, so faster devices do more without anyone setting it up.

The iPhone had left the pool before this run. Its screen locked and the browser paused the page, which is one of the open problems below. The prototype also renders fractals, estimates π, searches shared files, and runs code you write yourself.

What can be pooled

Devices talk over Wi-Fi, and Wi-Fi is far slower than the inside of a computer. The pool never pretends to be one big machine. It splits work so that each device computes on its own memory, and only inputs and results cross the network.

Training a large model across home devices isn't practical, because the data the devices must exchange at every step is too large for Wi-Fi. Running models and small fine-tunes, such as LoRA adapters, are within reach.

Which device does what

Computers run the agent

MacWindows PCLinux
  • A small background program, installed once
  • Shares processors, graphics, memory for model slices, and disk for shared storage
  • One of them hosts the Linux workspace. Here that is the Windows PC, through WSL2.

Phones and tablets join from a browser tab

iPhoneiPadAndroid
  • Nothing to install. Scan a code and the page joins.
  • Shares processors while the page is open and the screen is on, because iOS doesn't let apps keep computing in the background
  • A browser tab gets only part of the device's memory, so phones don't hold model slices or storage

  • CoordinatorKeeps track of devices, accounts and scheduling. Hands out pieces of work and knows which device holds which chunk of every file.
  • AgentRuns on each computer. Reports real processor, memory, graphics and disk, runs jobs natively, stores chunks, and serves model slices.
  • Web clientThe page phones and tablets use to share compute, and the dashboard every device sees.
  • WorkspaceA Linux environment you open as a terminal from any device. The pool is built in: a /pool folder, the harness command, and a Python call like pool.map().
  • Model runnerSplits a model across devices by how much memory each one has free, and serves it inside the workspace.

The backend is moving from Node to Python, because the tools people will run on the pool, such as PyTorch, llama.cpp, MLX and Hugging Face, are Python-first. Parts that move a lot of data can move to Rust later if they need to.

Roadmap

  1. Building now

    Foundation

    Python coordinator and agent. Real sign-in in place of the six-digit PIN. The Linux workspace in the browser, hosted on the Windows PC. Python jobs alongside JavaScript ones. Devices that stop responding lose their pieces within seconds.

  2. Next

    Shared storage

    Files cut into chunks, two copies of each on different devices, mounted as /pool in the workspace. When a device leaves, the pool makes new copies from the ones that remain.

  3. Then

    Models across devices

    harness model run splits a model's layers by free memory and serves a chat endpoint inside the workspace, so a 4 GB laptop can run a model that needs 8 GB.

  4. Then

    Phones on graphics

    HTTPS by default, which browsers require for WebGPU. Graphics kernels for iPhone and iPad, and pairing codes instead of long links.

  5. Later

    Beyond one home

    Pools shared between people over the internet, with the isolation that running code on someone else's device demands.

Who else works on this

exo

Open source, from exo labs. Runs AI models split across home devices, iPhones included. Focused on running models.

Petals

Splits a model's layers across volunteers' machines over the internet, in the style of BitTorrent.

Ray

The standard for distributed Python compute. Built for clusters of reliable servers in a data center.

YourHarness starts from the workspace. It is one place to work, where every device you own shows up as compute, memory and storage, and it is built for devices that sleep, move around and drop off Wi-Fi.

Open problems

  • Keeping phones in the pool. Browsers pause pages that aren't on screen. In the run above, the iPhone dropped out when its screen locked.
  • Wi-Fi bandwidth. It limits how fast model slices can pass results along. A desktop on a cable helps more than a faster phone.
  • Memory a browser will give. A tab gets only part of a phone's memory, and Safari doesn't report how much the device has.
  • Trust. Anyone in a pool can run code on its devices. Pools that reach beyond one home need real accounts, permissions and sandboxing first.
